## P02 local runtime boundary (implementation, not qualification)

The later coordinator receipt `nov13-p01-local-acceptance-v1.json` accepted the
local P01 prerequisite. Earlier lock statements above remain historical.
P02 adds only the toolkit-owned pure Python reference core under
`netops/ansible/policy/{__init__,contracts,loader,engine}.py`, with same-package
`_validation.py` centralizing the closed fact/event/numeric predicates shared
by load, decision and state restoration. The accepted PX, contracts, generated
bundle, corpus and build helper are not edited. Their installed proof still
binds its original exact revision, not this new runtime source.

`load_policy(bytes, bytes, bytes, PolicyIdentity)` independently checks packaged
identity, raw asset hashes, producer content digest, full one-to-one
declaration/path manifest, declaration order, every expression/action and every
example before returning an immutable `PolicyProgram`. Expression validation
visits dead branches; examples retain the nine full-event variants while
accepted target-local sparse fixtures remain loader-only data. Source bytes
are identity operands, not parsed with a second PX parser. Only the producer's
compact sorted UTF-8/LF representation is accepted; content-hash verification
removes the exact root digest member from original bytes so Python cannot
normalize the producer's float spelling.

`LocalReferencePolicyEngine` implements exactly `LocalPolicyPort.decide` and
`reduce`. Frozen dataclasses/string enums and recursively immutable mappings
carry typed, credential-free values. Unknown paths/fields, missing applicable
facts, duplicate identifiers, profile/reducer drift, invalid metadata,
unrepresentable counters, nonfinite values, mixed comparisons and float equality
fail closed before a result can authorize anything. The interpreter supports
only literal/path/not/paren and the eight closed boolean/comparison operators.
There is no dynamic action map, callback, `eval`/`exec`, executable, I/O, clock,
bootstrap or external-runtime dependency.

Program admission requires exact recursive DTO classes: mutable lookalikes and
subclasses are rejected before their fields/equality can become retained actions.
The loader stores original source/contracts/bundle bytes as a private
`PolicyProgram` field excluded from init, repr and comparison. Construction
revalidates their original hashes and reloads the full projection, then compares
all public program fields. A second asserted digest or a frozen semantic copy
cannot attest the old identity. No public constructor/wire signature, canonical
asset, profile or host admission contract changes; callers reload rather than
construct or replace programs. The bytes are immutable local proof, not secrets,
qualification or a Python sandbox boundary.

Constraints precede rules. Missing admit denies. Conflicting/duplicate actions,
multiple transitions/dispositions/effect rules and evaluation-budget exhaustion
raise without returning partial effects. Rule IDs are sorted/unique; intents
retain source/action order. `reduce` validates restored identities, namespace,
revision, selected disposition index and pending invocation/effect correlation;
it proposes the old expected revision and a new frozen state. Duplicate last
events produce no repeat intent. Final aggregation requires exact complete
selected coverage, including policy-derived failed health dispositions.
Dependency/qualification outcomes do not overwrite their lifecycle phase.
No checkpoint, reservation, grant or dispatch is produced by reduction.

Intermediate completion counters allow a pending remainder and are checked
against the complete selected disposition index after recording the one
correlated invocation/effect. Final counter consistency is reserved for an
actual complete outcome with no pending selected entry, no remaining lifecycle
occurrence and no next intent. Pending entries and once-only receipts survive
continuation. Only the frozen selectors' additional StepCompleted cases extend
normal phases: Verified/install activation, and Admitted/uninstall uninstall or
pointer restoration. This does not broaden other wrong-event/phase cases or
implement trusted occurrence-prefix hydration (still A01/A02 and I01/I02).

A health pass cannot overwrite a failed, blocked, unsupported or cancelled
observation disposition. Successful factual work still fails/marks unsupported
under its health finding; factual failures keep their category and digest.
The combined observation summary uses failure, cancellation, unsupported, blocked,
then success precedence. Subsequent final counters must cover those factual and
policy-derived dispositions; a healthy reading is never connectivity proof.

The host broker/CAS, original deadline, trusted evidence, consequential receipts,
actual activation, cancellation and pending-effect reconciliation are not
implemented by P02. Pure allow is neither qualification nor a permit. The
engine emits no log/metric side effects; authorized execution must later
