# Pure companion workflow contracts and planning

## Native provenance and Windows preservation correction

Pure comparison distinguishes exact paired versioned source provenance from
explicit native style selectors. Matching namespaced parser/vendor revisions
use the native autodetection seam without changing supplied case, line endings,
final newlines or input digests. The complete binding and credential/syntax
guards remain mandatory; a nonsecret SNMP notification is not permission for
neighboring credentials or raw protected configuration. See the
[comparison contract](../change/change-architecture.md).

Windows publication retains the verified source DELETE handle and its pinned
parent chain. `SetFileInformationByHandle(FileRenameInfo)` uses a NULL
`RootDirectory` and the absolute UTF-16 destination, not a relative-name fixture
with a non-NULL parent. This is a native ABI constraint, not a path-based
replacement or a relaxation of parent/member containment.

After actual process wait and job-absence proof, partial handle finalization
closes every closeable owner, retains only failed handles, and retries only
those remaining handles. An already closed process must remain zero while a
failed job close is retained; it must not be leaked merely to preserve an old
fixture expectation. No new close tolerance, warm-up, name kill, global process
scan or WSL/Linux qualification is introduced.

## A02 owned lifecycle I/O observations (PX11/T32)

`OwnedLifecycleState` wraps actual owned-record reads (including validation) and
compare-and-replace calls with the shared `ArtifactObservations` I/O helper.
Facts, pointers, inert copies/tombstones, probe inputs and factual receipts all
use those boundaries; no extra dispatch, read, write or retry is introduced.
Each start and terminal event carries `netops.lifecycle.owned_io.count` with
value 1 and bounded `boundary` (`owned_read`, `owned_cas`) / `outcome`
(`started`, `succeeded`, `failed`) dimensions. The helper maintains matching
process-local aggregate counters. A process-local `io_id` correlates the pair
only in logs. Each record also has `operation_id` (install/restore/uninstall
plan), `step_id`, `occurrence_id`, `target_id`, `context_id`, `mode`, `status`,
`error_category`, `reason`, `retryable` and `next_action`. Correlation fields are
deterministic `sha256:` references to the bound identifiers, not raw caller
strings; lifecycle work has no device target (`target_id="none"`).
ContextVar scopes isolate concurrent operations, preserve occurrence correlation
through nested owned locks and reset on exit. Admission/snapshot work has
`step_id`/`occurrence_id="none"` where no occurrence is entered; direct unscoped
adapter calls use `"none"` correlation. These observations never supply authority.
Only `boundary`/`outcome` enter aggregate labels; no high-cardinality correlation,
resources, paths, payloads, grants or exception text are included in those labels.
Duration is finite nonnegative monotonic seconds, with
zero fallback for unavailable/invalid reporting clocks.

The terminal pair is emitted in `finally`, including `BaseException` failures.
Reporting clock/sink failures never change admission, suppress original I/O
exceptions, invalidate returned facts or discard late persisted receipts.
No new public API or exporter configuration is introduced. This documents local
inert-owned adapter observations, not qualified native controller I/O, S02
platform acceptance, or full A02/feature acceptance; independent recheck remains
required.

Successful/start I/O records have `error_category`/`reason`/`next_action="none"`.
Failed records use the closed `storage` / `owned-io-failed` classification,
`retryable=false`, and fixed guidance to inspect the owned receipt/current state
before a new reviewed attempt. No exception message or raw path is copied.
Native execution observations and bare `lifecycle.handler.started/succeeded/failed`
records also isolate all reporting exceptions (including interrupting sinks).
Counters/logs are attempted once, never retried after partial emission. A sink
failure cannot replace native payload/status, primary failure, cancellation,
secondary cleanup, or an already persisted observed lifecycle receipt.

The shared helper owns the metric name and the closed boundary/outcome
vocabularies as module constants. Unknown boundary names are rejected before
entering I/O or emitting records. Regression controls pin raw metric/dimension
strings and compare actual local counter increments with the structured pair;
they do not stand in for exporter delivery or independent acceptance.

## Data flow and trust boundary

1. Application bootstrap reads selected policy assets outside pure calls,
   verifies them using `load_policy`, and injects `LocalReferencePolicyEngine`.
2. The caller constructs or strictly decodes `OperationRequest`. Schema, UUID,
   operation/mode, ordered unique scope and all nested fields are checked before
   dispatch. Public requests cannot carry consent or executable extensions.
3. Explicit `hydrate_inputs` reads only already-selected immutable bytes or
   checked read-only regular-file descriptors, validates bounded credential-free
   data/provenance, and returns `LoadedInputContext`.
   It binds default settings. Explicit bootstrap may separately load protected
   stored settings, resolve allowed tuning and call pure `bind_settings` to
   bind that exact snapshot into the runtime loaded context. Neither public
   request nor context JSON accepts a settings/override channel. The constructor,
   hydrator and preview signatures are unchanged.
4. `preview` reconstructs and revalidates the request, exact contents, source
   identities and complete observation binding in memory. It computes a
   deterministic planning event and invokes only `LocalPolicyPort.decide`.
   Requested effectful modes are represented as pure planning events, not
   consented operations. No `reduce`, persistence or reservation occurs.
5. The returned plan binds selected target order, resolved/unresolved routes,
   request/input/policy/registry/assets identities, reducer version, would-effects,
   observations, output intent, the same immutable settings snapshot and explicit
   unmet preconditions. Settings changes invalidate loaded/plan digests.

Content SHA256 follows bounded nonsecret validation. The centralized text
boundary rejects supported SNMPv3 auth/priv and TACACS/RADIUS inline/block key
syntax in addition to generic credential/private-key statements. Recursive
structured checks include camelCase/snake_case auth/privacy/shared-key fields.
Known compact/case aliases and SNMP communities are rejected too; unsupported
structured credential-domain objects fail closed. SNMP security-level-only
group/host declarations and nonsecret AAA identifiers retain native diff parity.
Authentication/privacy tokens are interpreted in credential parameter positions,
not as family-wide bans: SNMP authentication-trap notification selection
(including case-insensitive and negated forms) remains nonsecret. Every line
still undergoes credential validation before content hashing or native projection.
No raw sensitive configuration is projected into native diffs or public hashes;
source bytes are hidden from repr. This is fail-closed handling of supported
credential forms, **not** perfect regex/vendor-secret certification; protected
recovery configurations and unknown credential encodings are not public inputs.
Username/password/secret fields are not sanitized by hashing. Hydration metadata and planning
observation ages are never execution freshness authority. A context-supplied
policy identity must be the identity validated at bootstrap; the actual policy
decision checks its bundle digest. The later host must independently revalidate
all current identities and private admission bindings.

Canonical JSON sorts object keys, not ordered target/command/group arrays.
Public JSON objects are recursively detached and canonicalized for stable DTO
round-trips. Input byte identity remains exact, including whitespace. The plan
digest excludes only its own field; the request binding excludes the previous
plan's self-referential digest. Observation identity/provenance remains bound.

## Side-effect and failure model

`catalog` is a declaration surface, not I01's registry or functional readiness.
`preview` cannot read clocks/resources/paths, probe/unlock/connect, call any
effect port, emit telemetry or bootstrap a logger. It returns safe diagnostics
in memory. A selected missing/swapped/extra/tampered input raises a safe
`input-binding-invalid` `ContractError`, never an implicit reload. Missing
observations instead produce per-target preconditions. Routes not resolvable
from supplied inventory remain represented and explicitly blocked.
C01-produced preview diagnostics use one closed frozen-matrix mapping with
actionable guidance: unresolved routes are `transport / route-unavailable /
connect`; unavailable dependencies are `dependency / dependency-not-ready /
readiness`, shared with blocked execution. Observation/stale-consent conditions
remain `precondition / authorize`, consequential missing consent uses
`platform / provision`, and rejected output intent uses `rendering / publish`.
The existing policy-denial diagnostic retains its separate `policy / authorize`
classification; evaluator faults remain internal failures, not caller errors.
Valid-bound policy input/evaluation/budget errors instead raise `PolicyFailure`:
an in-memory allowlisted internal cause plus existing public
`policy / reading-unavailable / evaluate` error, exit 5 and safe evaluator-repair
guidance. A malformed evaluator result also uses this failure boundary. Raw
exceptions are never copied. Surface adapters preserve this error in their
ordinary failed outcome, not the caller-invalid exit 2 path.

Settings use frozen nested groups and complete schema-1.0 JSON. The API reference
lists every original table setting, default and range, including native-owner

### Partial A02 owned event checkpoint adapter

`OwnedPolicyJournal` in the existing artifacts module composes the actual local
policy reducer with C02's `OwnedStatePort` lock and protected v1 CAS. Explicit
creation stores the first validated transition; appends retain the complete
bounded event/fact history. Recovery checks the complete current host-supplied
binding and owner/policy/generation identities, replays all events, and verifies
the derived state digests and exact checkpoint sequence. Historical duplicates
require both identical event content and source facts and return only the
original factual receipt, without a write or an executable effect.

An unresolved invocation recovers as `Uncertain`; no grant, session, credential
or permit is hydrated. The journal validates stored facts against the actual
reducer; it is not an independent current-source collector or an event's host
authentication. The host must independently verify current sources and
bindings. Neither the journal nor an apparently complete history authorizes a
handler. The partial gather/collect host now integrates this journal, repeated
current-source rechecks, private fixed entry and ordered resource locks. Other
handlers, qualified concrete readers/backends, real OS-admission evidence and the
complete native result/cleanup/revert matrix remain original A02 obligations.

Aggregation matches the accepted PX rule precedence: mixed completed and
unsuccessful selected work is partial, otherwise failure precedes cancellation,
unsupported and blocked. Cleanup and uncertainty are independent of primary
results. Unselected optional steps are excluded, never selected targets.
Selected success additionally requires attempted work with no pending effects.
DTO construction, response decoding and aggregation reject contradictory
completion, including deliberate frozen-object corruption. Mixed completed/
pending apply remains partial with changed/uncertain state preserved.
Findings cannot be inferred healthy from connectivity. Exact public native
payload numbers are not narrowed to policy int53; decision-bearing control
counters and finite deadline arithmetic are separately validated.
