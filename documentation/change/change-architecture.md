# Bound semantic comparison

Native `diff_configs` and `DiffResult` remain the semantic owners. Junos
bracketed syntax is detected explicitly. Duplicate native directives retain
every occurrence (including the third and later duplicates); matching remains
order-normalized, not an implicit change execution.

The companion validates exact immutable before/after bytes, kinds, content
digests, one-to-one request binding and equal parser/vendor revisions without
reopening refs. Supported parser selectors are the retained `parser-1` native
autodetection identity and explicit `cisco`, `junos`, `flat`. The retained
`vendor-1` identity is opaque paired native compatibility; known Cisco/Arista,
Juniper and Nokia identities select the corresponding native style. Namespaced versioned source provenance is distinct from those style selectors:
`<namespace>-parser-v<positive revision>` must be paired with the same
`<namespace>-vendor-v<positive revision>`. The namespace consists of lowercase
alphanumeric segments separated by hyphens, beginning with a letter. Both
snapshots retain exactly equal complete parser/vendor revisions, and every
revision remains included in the loaded binding digest. This source identity
uses native autodetection, not an inferred vendor command or execution grant.
It is not a prefix whitelist for a particular caller or an SNMP exception.
Unknown selector forms or mismatched identities fail closed. Bracketed Junos requires balanced native
line-oriented syntax; unsupported inline/mixed formats are not silently parsed
as an empty no-change configuration.

Outputs expose native diff semantics plus deterministic unmatched/missing/drift
counts. Empty snapshots are explicitly blocked/missing, not healthy no-change.
No collection, credential lookup, filesystem read, clock or log occurs in
preview/check. Requested target observations remain unmet preconditions when
absent. Ordinary native diff defaults and output formats are retained.

Protected credential-bearing recovery configurations may not enter this public
comparison boundary. Supported credential syntax rejects before hashing.
Public native diffs can contain explicitly supplied nonsecret configuration;
they are not certified redactions of protected device configuration.

Case, line endings and final newlines reach `diff_configs` unchanged. Native
semantic normalization belongs to that owner; companion grammar and supported
credential rejection still run first. Nonsecret SNMP notification selectors
(including `authentication`) preserve the native result, while adjacent SNMPv3
auth/priv values, AAA keys, raw protected configuration, forged device/controller
identity, missing input and changed content digests remain rejected.

The fixed host drafts local YAML-only `compare.generate` publication using the
already validated native projection. It remains blocked by the current
factual-only compare policy, which has no executable `save` intent for A01.
Neither generated bytes nor factual policy success is authority to collect,
apply or publish. Independent output integration and the coordinator's narrow
policy disposition remain mandatory, without changing this native diff API.
